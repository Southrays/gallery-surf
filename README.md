# Gallery Surf

A local, offline-first desktop app for culling a photo shoot: point it at a folder, flip through the images, mark what to keep, then copy or move the picks to a destination folder. No cloud upload, no account, no network dependency — everything happens on disk.

Built with Electron, React, TypeScript, and Vite (via `electron-vite`).

## Features

- **Folder-based workflow**: pick a source folder (optionally including subfolders), review it, then move into a culling session.
- **Grid and Loupe views**: a thumbnail grid for a quick pass, and a full-size Loupe view with a filmstrip for close inspection, with fast keyboard-driven navigation.
- **Broad format support**: JPEG, PNG, HEIC/HEIF, and RAW (CR3, CR2, NEF, ARW, DNG, RAF, RW2, ORF). RAW/HEIC previews are produced by extracting the camera's own embedded JPEG preview rather than a full raw decode, so browsing stays fast.
- **Fast navigation on large folders**: thumbnails and previews are generated on a priority queue — whatever you're actually looking at always jumps ahead of background prefetching, so flipping through hundreds of photos stays responsive.
- **Full screen (immersive) Loupe mode**: strips the UI down to just the image plus a selected/rejected indicator and photo count.
- **Review step**: see everything you've selected before committing, with a one-click "clear all selections" (with confirmation).
- **Safe copy/move**: copies are verified before anything is deleted — a Move only removes the original once its copy has been confirmed on disk. Live progress is shown for the whole batch, with cancel support.
- **Persistence**: selections, the recent-projects list, and UI preferences (subfolder toggle, filmstrip size) all survive closing the app.
- **Recent projects**: quick re-entry into folders you've worked on before, capped at the 10 most recent.

## Keyboard shortcuts

| Key | Action |
| --- | --- |
| `S` | Select current photo |
| `R` | Reject current photo |
| `G` | Switch to Grid view |
| `E` | Switch to Loupe view |
| `←` / `→` | Navigate to previous/next photo |
| `Space` | Toggle zoom (Fit / 100%) |
| `Ctrl`/`Cmd` `+` / `-` | Zoom in/out on the current photo (in Grid/Loupe), or zoom the app's own UI everywhere else |
| `F` | Toggle full screen (Loupe only) |
| `Esc` | Exit full screen |

## Requirements

- Node.js 18 or later
- Windows or macOS (Linux is not an explicit target, though the underlying stack supports it)

## Getting started

```bash
npm install
npm run dev
```

This starts the app with hot-reload for the renderer and automatic rebuilds for the main/preload processes.

## Building a distributable

```bash
npm run build:win
```

Produces `dist/Gallery Surf Setup <version>.exe` — an NSIS installer with an assisted (non-one-click) install flow: the user can change the install directory, and desktop and Start Menu shortcuts are created. The installer and app icon are generated by electron-builder from the assets in `build/`.

The build currently ships **unsigned**. If you see an `EPERM ... rename` error on Windows partway through packaging, it's Windows Defender briefly locking the freshly-extracted Electron binary during on-access scanning — delete the leftover `dist/win-unpacked.tmp` folder and re-run the build.

`sharp` (used for all image decoding/resizing) ships a platform-specific native addon, which can't be loaded from inside an `asar` archive. `electron-builder.yml` unpacks `sharp` and its `@img/*` binary packages via `asarUnpack` so the packaged app can actually load it — this is load-bearing configuration, not an optional tweak.

macOS packaging (`build:mac`) is configured but not exercised in this repository; it needs to be built and tested on a Mac.

## Project structure

```
src/
  main/         Electron main process — window/lifecycle, folder scanning,
                 image preview generation, copy/move, IPC handlers, all
                 persisted state (recents, settings, per-folder selections)
  preload/      contextBridge-exposed API surface between main and renderer
  renderer/     React + TypeScript UI (screens, components, hooks, state)
  shared/       Types shared between main, preload, and renderer

build/          electron-builder resources: app icon, installer graphics
electron-builder.yml   Packaging configuration (NSIS/dmg targets, asarUnpack)
electron.vite.config.ts   Build configuration for all three processes
```

### How image previews work

Plain JPEG/PNG files are decoded directly with `sharp`. HEIC/HEIF is decoded natively where the bundled `libvips` supports it, falling back to the same technique used for RAW formats: the largest embedded JPEG preview is extracted directly from the file (a byte scan for JPEG start/end markers) and decoded from there, rather than performing a full RAW demosaic. This is the same approach fast culling tools use, and it means CR3/NEF/ARW/etc. preview at speed comparable to a JPEG.

Orientation gets special handling for RAW files: the extracted preview frequently carries no EXIF orientation tag of its own (the camera stores it once, on the parent file), so orientation is read from the parent container's TIFF header and applied explicitly when needed.

### Where data is stored

The app keeps its cache and persisted state in Electron's per-OS user data directory (`app.getPath('userData')`), not inside the project or the photo folders themselves:

- `thumbs/`, `previews/` — generated preview cache, keyed by file path + modified time + size
- `recents.json` — recent projects list
- `settings.json` — UI preferences (include-subfolders toggle, filmstrip height/collapsed state)
- `selections/` — per-folder selected/rejected flags, keyed by photo id so a replaced file doesn't inherit a stale pick
